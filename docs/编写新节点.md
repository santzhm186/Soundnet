# 编写一个新节点

本轮重构之后，新增节点不再需要修改六份互相独立的名单。以“增益（Gain）”节点为例，完整步骤如下。

## 1 在描述符里登记

编辑 `src/NodeSpec.hpp`，在 `nodeSpecs()` 的表中追加一条（顺序即节点库顺序）：

```cpp
add({"soundnet.gain",GainNode,"增益","处理",1,1,true,true,
     CapStream|CapBypassable,TimeMode::Stream,0,
     {pin("audio","音频",Signal::Audio,RoleMain,0)},
     {pout("audio","音频",Signal::Audio,RoleMain)},
     {GainAmount}, nullptr});
```

同时补三样东西：

| 内容 | 位置 | 说明 |
| --- | --- | --- |
| 类型编号 | `NodeSpec.hpp` 顶部 | 追加 `inline constexpr int GainNode=47;`，只增不改 |
| 参数 ID | `NodeSpec.hpp` 参数区 | 追加 `inline constexpr int GainAmount=1310;`，只增不改 |
| 参数条目 | `paramSpecs()` | `add(GainAmount,gainAmountInfo,"gain.amount",false);`；若是枚举，再用 `option(...)` 附上按值顺序排列的标签 |

完成这一步，节点已经出现在：

- 右键插入菜单与左侧节点库（`nodeCatalog` 由描述符派生）；
- 拖放校验（`nodeMeta`）；
- 检查器（`nodeParamList` 生成控件，范围/默认值/是否取整/枚举下拉都来自 `ParamSpec`）；
- 连线校验（端口信号、角色、单源/多源、拓扑排序）；
- 保存与打开（`nodeKey`、参数键、端口名自动写出与解析）；
- 离线导出与分轨（按 `CapOutputSink` 与 `CapStream` 判定）。

## 2 实现内核

`src/InstanceGraph.hpp` 中按能力接线，而不是按“这是第几号节点”接线：

1. **实时音频处理器**：在 `src/DspNodes.hpp` 写一个 `AudioProcessor`，并在 `makeAudioProcessor()` 注册。`publish` 会自动 `prepare()` 与下发参数。
2. **音符/定时节点**：在 `render()` 中用 `entry.inputs` 里声明的端口角色取输入，不要读固定下标；需要时钟时用 `entry.clock`，需要侧链时用 `entry.sidechain`。
3. **有独立状态的节点**：在 `Runtime` 中增加状态成员并在构造函数创建；所有状态必须能在 `reset()` 中重建。
4. **触发类节点**：在 `deliver()` 增加分支，声明它是立即投递还是延后一块。

实时路径必须保持有界：不分配内存、不访问文件或网络、不阻塞。需要分配的准备放在 `prepare()` 或控制线程。

## 3 写测试

最少三条：

1. 描述符自检通过（`tests/NodeSpecTests.cpp` 已经对所有注册节点做通用检查，新增节点自动纳入）；
2. 行为测试：构造 `GraphSpec`，用**端口名**连线，断言渲染结果或事件序列；
3. 文档往返：在 `tests/WorkflowFormatTests.mm` 增加一条 v4 文档用例，确认参数键与端口名能读回。

## 4 规则清单

| 规则 | 原因 |
| --- | --- |
| `nodeKey` 一经发布不得修改 | 它是工程文件的身份，改了旧工程就变成“缺失节点” |
| 端口 ID 不得修改；顺序只可追加 | v3 序号与描述符顺序一致，重排会错接旧工程 |
| 参数 ID 与参数键都不得复用 | 旧工程会读到错误语义 |
| 删除节点/端口/参数时保留占位 | 让旧工程能解释“这里原本有什么” |
| 行为变化要提升 `nodeVersion` | 平台据此拒绝用新语义渲染旧工程 |
| 新增能力用能力位，不加类型判断 | 引擎按能力工作，第三方节点才能接上汇总、分轨与旁通 |

## 5 何时需要改平台代码

只有三种情况需要改 `InstanceGraph` 之外的公共代码：

1. 新增**信号类别**（例如 `Control`）需要桥接节点；
2. 新增**执行能力**（例如异步任务、快照）；
3. 新增**时间语义**（例如内容时间的定点触发）。

这三种都属于契约变更，应先更新 `docs/节点与连接标准-实现映射.md`，再加实现，避免节点先行、契约滞后。
