# 编写与适配节点（2.9.1）

开始前阅读 [项目宪法](项目宪法.md)。新节点使用独立目录与公共内核工厂，不向中央渲染器增加类型分支。

## 1. 新建模块目录

以 `nodes/gain/` 为音频样例，以 `nodes/midi-split/` 为有状态多出口样例，创建自己的目录，例如 `nodes/my-effect/`。

```text
nodes/my-effect/
  Node.hpp
  Kernel.hpp
  Tests.cpp
  Editor.hpp    可选的专用界面
```

`Node.hpp` 必须包含发现声明，目录连字符在 C++ 命名空间中换为下划线。

```cpp
#pragma once
#include "../../platform/NodeDescriptor.hpp"
#include "Kernel.hpp"
// soundnet-module: example.my-effect
namespace tri::nodes::my_effect {
inline NodeModule module() {
    // 返回此节点的 NodeSpec 与本地参数表。
}
}
```

用 `nodeTypeID("example.my-effect")` 生成内部类型，用 `parameterID("example.my-effect", "amount")` 生成参数 ID。工程中的参数名可以仅为 `amount`，作用域是本节点。不要照抄其他节点的数字编号。

参考 `nodes/gain/Node.hpp` 设置端口、参数、分组和 `kernelFactory`。文本使用 `TextSpec`。多参数约束放入 `validateConfig`，失败返回清楚原因。

平台为 `validateConfig` 与 `configure` 使用同一配置解析规则：缺省数值和文本由描述符补齐，显式空文本保留为空。素材只按 `CapAssetAudio/Clip/Model` 声明传入；校验未解码的工程文档时素材可能尚不存在，验证器应允许这种情况。

SDK 1 的多源输入仅支持 `Signal::Trigger`，须声明 `PortMultiSource`；相同来源端口的重复连线只投递一次。`RoleTrigger` 必须配合触发信号。`PortOptional` 表示缺连接时不显示完整性提示；未声明者缺连接会产生非致命提示，仍允许编辑，内核必须处理空输入。SDK 1 拒绝 `PortFeedback`，确定延迟的反馈路由须作为后续平台接口扩展；旧适配节点保留历史反馈行为，不保证固定一块延迟。时间码输入接 `timecode` 或其他提供公共时间码的内核。

当前 `Node.hpp`/`Editor.hpp` 是自动发现的包含入口，实现可继续拆成目录内头文件。任意新增 `.cpp` 或随包资源不会自动参与编译/复制；确有需要时按宪法扩展公共发现规则。纯后台节点可像 `task-example` 一样使用 `Task.hpp`，无须空的 `Kernel.hpp`。

把专属显示文案与本节点一起声明：`NodeModule` 的第三个字段是 `translations`，条目为 `NodeTranslation{source, en}`，例如 `{{"增益", "Gain"}}`。`source` 建议用中文，平台也支持将英文参数标题反查为中文。标题、端口、参数、枚举及专用面板按当前节点查表，再回退公共文案；新节点无须编辑中央翻译表。每个方向的显示文案保持无歧义，格式占位符保持类型和顺序一致。用户填写的文本和稳定 ID 不翻译。

## 2. 实现内核

`Kernel.hpp` 只包含公共 SDK 和算法自身依赖，不包含其他节点或旧引擎。

```cpp
#include "../../platform/NodeKernel.hpp"

class Kernel final : public tri::NodeKernel {
public:
    void prepare(double sampleRate, int maxFrames) override;
    void configure(const tri::KernelConfig& config) override;
    void process(tri::KernelContext& context) noexcept override;
    void reset(tri::KernelResetReason reason) noexcept override;
};
```

`prepare/configure` 完成内存和配置准备。`process` 用 `context.input("端口名")`、`context.output("端口名")` 获取本次视图，按 `context.frames` 处理有效帧。输入可能缺省，输出与事件队列有明确容量；处理溢出并保持音符收放配对。`process/reset` 不分配、不等待、不访问文件/网络或调用模型推理。

每个实例拥有独立状态，不把可变播放状态放在静态变量。参考 `midi-split` 在参数变化后仍把 Note Off 发回原来的出口。

素材从 `KernelConfig.audio/clip/model` 获取，公开类型定义在 `platform/resources/`。这些是准备阶段已经解码的 `shared_ptr<const ...>`；在 `configure` 保存句柄，`process` 只读内容，不解码、不复制大块素材、不替换句柄所有权。无需通过其他节点或 `src/` 私有头文件读取素材。

## 3. 时间与节奏

需要时间时使用时间码输入或上下文帧位置和代次。节点自行声明 BPM、拍号等音乐参数，在公共时间轴计算事件。不要读取或新增项目全局 BPM，不新增独立节奏节点。

普通计算可不读取时间，音频处理仍使用会话采样率。定位或停止后按复位原因清理旧时间状态。

## 4. 后台任务与专用界面

耗时工作使用 `platform/TaskService.hpp`。提交前固定输入快照，绑定节点和输入版本；接受取消，完成后仅由有效归属领取结果。外部进程协议放在本节点目录，例如 `nodes/ai-music/Backend.hpp`。

参考隐藏样例 `nodes/task-example/`：描述符声明 `CapTask`，专用面板用 `NodeEditorContext.submitTask` 提交拥有不可变输入的工作函数和结果应用函数，使用 `cancelTask` 取消、`taskSnapshot` 查询。平台限制其作用范围为当前工程和节点，并在控制线程调用结果应用函数；该函数返回替换配置，再由平台统一验证与提交。工作线程不修改工程或 Cocoa 控件。纯后台模块不需要音频内核或中央类型分支。

普通数值和文本控件由描述符生成。可选 `Editor.hpp` 实现 `tri::nodes::<slug>::editor(NodeEditorContext)`，由 `GeneratedEditors.hpp` 自动发现，仅 UI 构建包含 Cocoa。参考 `nodes/project-settings/Editor.hpp`。

专用面板通过 `NodeEditorContext::commit` 提交完整节点配置，走统一校验、撤销、保存。不要直接修改运行内核。扩展公共面板能力时按宪法记录接口变化并适配使用方。

专用面板用 `context.text(@"本节点显示文案")` 查节点翻译，无须导入 `ui/`。公共 UI 的对应接口是 `SNNodeLocalized(type, source)`，测试可用 `SNNodeLocalizedForLanguage(type, source, english)`；节点内核不读取界面语言。

## 5. 自动发现与验证

```sh
python3 scripts/generate-node-registry.py
python3 scripts/generate-node-registry.py --check
xcrun clang++ -std=c++17 -O2 nodes/my-effect/Tests.cpp -o /tmp/my-effect-tests
/tmp/my-effect-tests
# 或使用独立模块入口
./scripts/test-node.sh my-effect
./scripts/test-all.sh
```

生成器检查名称和目录冲突，原子更新 `nodes/GeneratedRegistry.hpp` 与 `nodes/GeneratedEditors.hpp`。生成文件随代码提交，但不手工维护。App、AU 和测试构建入口都会重新检查/生成。

`test-all.sh` 自动收集 `nodes/*/Tests.cpp`，新增模块不用修改测试名单。平台集成测试在 `tests/`，`NodeModuleTests` 检查注册、接口、多出口与配置校验，`KernelIntegrationTests` 检查实际图执行。

至少覆盖真实行为、空输入、短块、参数边界和停止。有 MIDI 输出验证配对与断线收音，有后台任务验证取消与过期结果。声音测试断言可测量的输出，不只检查没有崩溃。

版本从 1 开始：`nodeVersion` 范围 1–65535，`stateVersion` 范围 1–255；当前工程加载要求与模块声明精确相等。变更行为或已保存配置的含义时更新相应版本，并说明现有实例需重建或采用明确转换；仅修改显示文案无需升级。`sdkVersion` 只跟随公共平台接口演进。当前没有通用私有运行状态读写回调，不要把 `stateVersion` 当作自动保存/恢复内存状态的实现。

## 6. 适配已有节点

既有 `Node.hpp` 已独立，音频算法在所属节点的 `Processor.hpp`，部分 MIDI/合成算法在 `LegacyRuntime.inc`，仍可能走旧适配路径。`nodes/_legacy/` 保留过渡引擎和处理器注册。迁移时按以下顺序执行。

1. 确认端口、参数、单位、状态和已有行为测试。
2. 将算法与实例状态迁入本目录 `Kernel.hpp`，只依赖 SDK。
3. 声明 `kernelFactory` 与配置校验，补独立 `Tests.cpp`。
4. 验证内核通过真实图运行，按节点自身节奏使用时间码。
5. 移除描述符的 `legacyAdapter` 和 `nodes/_legacy/adapter-keys.txt` 对应条目，删除已无调用的旧实现分支，确认其他节点没有依赖它。
6. 更新实现映射中的适配状态与限制。

`nodes/_legacy/` 是过渡代码。生成器同时检查 `legacyAdapter` 和既有适配清单；普通新增节点不得扩充清单或依赖旧引擎，不能通过继续扩大中央分支声称完成模块化。
