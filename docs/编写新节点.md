# 编写与独立发布节点（SDK 2）

先读 [项目宪法](项目宪法.md)。Soundnet 3.0.0 / build 100 是平台版本；节点包可独立更新。常规节点不改中央运行器、画布、宿主或构建名单。

## 1. 建立独立模块

```text
nodes/my-effect/
  Node.hpp
  Kernel.hpp
  Tests.cpp
  Editor.hpp       可选专用界面
  Resources/       可选随包文件
```

`Node.hpp` 写发现声明；目录连字符在 C++ 命名空间中替换为下划线：

```cpp
#pragma once
#include "../../platform/NodeDescriptor.hpp"
#include "Kernel.hpp"
// soundnet-module: example.my-effect
namespace tri::nodes::my_effect {
inline NodeModule module() {
    // 返回本节点 NodeSpec、本地参数与翻译表。
}
}
```

用 `nodeTypeID("example.my-effect")` 和 `parameterID("example.my-effect", "amount")` 派生 ID，不领取全局数字区间，不复制历史编号。参考 `gain` 的工厂、`midi-split` 的多出口状态和 `task-example` 的纯后台模块。

节点只包含本目录和 `platform/` 的公共头文件，不能依赖其他节点内部、`src/`、中央 UI 或宿主。额外 `.cpp/.mm` 在节点包构建时按目录收集，`Tests.cpp/Tests.mm` 和 `tests/` 目录排除；资源放 `Resources/`。不要为单个节点新增中央文件名单。纯后台模块可没有 `Kernel.hpp`，纯元数据模块可没有处理内核。

## 2. 描述配置和行为

端口使用稳定 ID，输入/输出各自在本节点内唯一。参数声明本地稳定名称、单位、范围、默认值、离散性和可选枚举；文本用 `TextSpec` 声明容量及读写属性。组合约束放 `validateConfig`，不在平台补节点例外。

平台给 `validateConfig/configure` 补齐同一套默认配置，显式空文本保留。未解码文档的验证不能要求素材句柄已存在。公共资源按 `CapAssetAudio/Clip/Model` 授予。

专属中英文放 `NodeModule.translations`，平台按节点类型隔离。面板调用 `context.text(@"文案")`；名称、端口、参数、选项与说明应提供两种语言。用户文本和稳定 key 不翻译。

```cpp
#include "../../platform/NodeKernel.hpp"
class Kernel final : public tri::NodeKernel {
public:
    void prepare(double sampleRate, int maxFrames) override;
    void configure(const tri::KernelConfig&) override;
    void process(tri::KernelContext&) noexcept override;
    void reset(tri::KernelResetReason) noexcept override;
};
```

`prepare/configure` 完成配置、内存和资源准备。`process/reset` 不分配、不阻塞、不访问磁盘/网络、不等待推理；按实际 `frames` 处理短块和变长块。空输入必须安全。输入只读，输出按 `context.output("端口ID")` 分别访问，不能假设多输出都在位置 0。

可变状态属于实例。 SDK 2 平台复位先释放跟踪的宿主 MIDI/控制器并清已发布输出，下游输入状态比对产生 Note Off；内核 `reset` 只清内部状态，不在下个 `process` 重复补发释放。MIDI 保留帧偏移和通道，停止、断线、参数改变、循环和溢出仍能收音；参考 `midi-split` 在音高分界改变后把 Note Off 发送回原出口。资源通过 `KernelConfig.audio/clip/model` 获取，配置时持有不可变句柄，不在音频线程解码。

## 3. 时间与图通信

需要节奏的节点自行声明 BPM/拍号，根据公共帧位置计算事件；无独立节奏节点或全局 BPM。下游不得重解释上游已经确定的帧时间。

节点自行定义宿主传输策略。MIDI Clip 在 `KernelContext.playing=false` 时释放已发音符和控制器并冻结片段游标，保留触发运行意图；恢复时按当前位置重建音符/控制器状态。暂停中的定位只更新位置，暂停中的触发仍更新 Start/Stop 意图，不发送片段事件。该策略不等于平台停用所有 `TimeMode::Timed` 节点，也不阻止其他节点提供实时 MIDI 试听。

SDK 2 支持音频、MIDI、触发和时间码。`Control/Resource/TaskEvent` 图端口未实现；仅增加枚举/描述符不能接通它们。`PortMultiSource` 仅用于触发输入，同源重复边只投递一次；`PortOptional` 控制未连提示，所有内核都须处理缺输入。

`PortFeedback` 仅允许触发输入参与反馈；编译器按强连通分量识别实际成环的边，只对环内声明允许反馈的边延迟产生事件时当前块的有效帧数并保留块内偏移。普通 Start→Clip 无环边同块传递。测试必须覆盖跨块循环及变长块，不能将该标志推广为任意 MIDI/音频回授。

## 4. UI、任务与工程资源

描述符的 `category` 按节点用途填写「音符」「发声」「声音处理」「走带与控制」或「工程与 I/O」。节点库和右键插入菜单共用分类。画布卡片依照 `NodeSpec.params` 的顺序显示前两项可见的非触发参数，沿用描述符的单位和枚举文案。声明音频素材的节点可显示已载入素材的波形缩略图。

`Editor.hpp` 提供 `tri::nodes::<slug>::editor(NodeEditorContext)`。普通控件自动生成，专用面板通过公共编辑回调提交配置、创建节点、试听 MIDI 或使用设备服务，不包含中央编辑器。提交支持撤销/重做和保存；省略字段表示保留，显式 `NSNull` 删除支持的字段。

后台工作声明 `CapTask`，经 `submitTask/cancelTask/taskSnapshot` 调用平台 `TaskService`。输入必须固定为任务拥有的快照；工作线程不接触工程/UI。平台绑定工程、实例、输入版本和任务 ID，只有仍有效的成功结果由控制线程应用。用户编辑输入、删除、切换工程或取消后，过期结果不能覆盖素材。

长期开着的面板先用 `captureTaskContext` 刷新配置及编辑/任务回调；失去选中实例或会话归属后不得提交。ACE-Step/YuE2 的任务与结果回写位于自身 `Task.hpp`，共享外部进程协议位于 `platform/musicgen/`。

所有需随工程保存的素材通过 `platform/ProjectResources.h` 管理：

- `importAsset`、`encodeClip/decodeClip`、`audioFileData` 提供公共编码/导入能力，不引用 `src/`。
- `assetResource` 和 `textResource` 构造带类型内容；`appendEntry` 将一组资源加入节点的命名集合，返回新配置。
- `collection` 读取有序记录；`entryResource` 按角色取得记录引用的资源，例如一个 take 的 `audio` 和 `score`。
- 整个节点配置通过正常编辑事务提交。资源表与集合留在配置中，AU 状态自包含；磁盘保存由平台统一转换成相对引用和同名 `.assets` 文件。

随节点包发布的 `Resources/` 与工程 `.assets` 不同：平台校验并保留包资源的不可变快照，通过 `KernelConfig.resourceDirectory`（C++ 字符串）和 `NodeEditorContext.resourceDirectory`（NSString）提供只读根目录。在配置或后台任务阶段读取，不在音频线程访问文件；资源文件单独更新也应触发刷新，旧实例继续持有旧快照。

不要存绝对历史素材路径，不让节点选择归档目录。`project.folder` 是平台工程根/未保存默认位置。未保存也保留完整资源历史；取消和失败不发布集合条目。参见 `platform/musicgen/GenerationArchive.hpp` 与两个生成节点的 `Task.hpp`。

文本若应作为独立素材保存，可设置 `TextSpec.assetExtension`，如 ABC 的 `"abc"`。平台 v6 `textRefs` 自描述类型；模块缺失时仍保留内容与引用。资源集合不是图内 `Signal::Resource` 通信，两者不要混淆。

## 5. 独立构建、安装与刷新

先准备与目标平台一致的 SDK 和 `libSoundnetPlatform.dylib`。平台开发者首次构建公共库；以后节点更新只执行节点构建：

```sh
./scripts/build-platform.sh build/platform
python3 scripts/build-node.py nodes/my-effect build/Nodes \
  --platform-library build/platform/libSoundnetPlatform.dylib
```

独立 SDK 根可用 `--sdk /path/to/sdk`；源码只依赖其 `platform/`。默认构建 arm64+x86_64 通用包，可用 `--arch arm64` 做本机开发。`all` 代替源码目录可批量构建 SDK 根的节点。

`build-all.sh` 同时输出 `Soundnet-Node-SDK/`，只包含公共头文件、已构建平台链接库、构建器与文档。也可执行 `scripts/export-node-sdk.sh /path/to/libSoundnetPlatform.dylib /path/to/SDK` 单独导出。独立作者在该 SDK 目录执行 `python3 scripts/build-node.py /path/to/my-effect /path/to/packages --platform-library lib/libSoundnetPlatform.dylib` 即可；不需要宿主源码或其他节点。导出 SDK 没有内置节点源码，因此只支持单节点构建；`all` 供完整源码仓库使用。

输出为 `build/Nodes/example.my-effect.soundnode/`：

```text
manifest.json       key、packageABI、sdkVersion、revision、library、sha256、资源校验
Node.dylib          导出 soundnet_node_v2
Resources/          可选资源
```

构建器自动生成固定 C 入口包装，检查 ABI/SDK 后才调用 C++ 描述符和 Cocoa 编辑器。公共结构布局、clang/libc++ 合同必须与平台匹配；这不是跨任意编译器的通用 C ABI。包构建修订与 `nodeVersion/stateVersion` 不同，勿为了重编译或文案变化随意提升行为版本。

将完整包放到 `~/Library/Application Support/Soundnet/Nodes`，在节点库刷新。App/AU 使用同一加载器，用户包可覆盖同 key 内置包。无须重编 Soundnet 或整个应用。开发测试可用 `SOUNDNET_NODE_PATH` 指定冒号分隔的绝对节点包目录，替换默认路径。

生产目录必须保留 SDK 2 指定的两个环境模块：`soundnet.timecode`、`soundnet.project-settings` 各一个，`nodeVersion/stateVersion` 均为 1，`environmentRole` 分别为 `Timecode`、`ProjectSettings`。其他节点不得冒充这些角色。生产 App/AU 使用 `refreshNodePackages(roots, true)`，缺少环境模块或版本、角色不兼容会拒绝整个刷新并保留旧目录及运行图。用 `SOUNDNET_NODE_PATH` 替换默认路径时也要提供这两个包。独立包测试可使用默认 `requireEnvironment=false` 加载局部目录；这不豁免生产目录的环境合同，也不意味着完整工程可以省略环境节点。

刷新是整批候选验证、原子发布新目录和工程重建；坏包/冲突不应破坏原目录。旧运行计划和面板保有所属代码，不热卸载 Objective-C 类；二进制镜像、包资源快照和注册目录修订各有 512 个的进程预算，到任一预算需重启。加载后才被拒绝的镜像同样计数，重复失败不会反复执行包入口；失败候选的临时资源清理，已接受快照不改写。该限制不同于每次节点更新都重启应用。

平台跨进程复用按哈希寻址的只读代码文件，并在复用前校验内容。代码缓存由平台维护，节点不能从其位置推导资源路径；读取随包资源始终使用配置/上下文给出的 `resourceDirectory`。

## 6. 测试与完成检查

```sh
./scripts/test-node.sh my-effect
python3 scripts/generate-node-registry.py --check
./scripts/test-all.sh
```

生成器收集 `nodes/*/Node.hpp` 和可选编辑器，供静态测试发现，不手改输出文件。全套脚本自动收集节点 `Tests.cpp`，无需新增测试名单。

独立测试覆盖真实输出、空输入、短块、参数边界、实例独立和复位。图测试覆盖端口身份、实际接线、多输出、反馈与停止；UI/任务测试覆盖事务、取消和过期结果。资源节点增加当前素材及全部历史保存、搬迁、重开、缺模块占位和缺素材诊断。更新包须测试同一平台中刷新生效、失败保留与旧代码寿命。

当前行为/状态版本精确匹配，无通用私有状态迁移和运行内存恢复。发布新行为版本时说明现有实例会占位或采用何种明确转换。公共接口修改运行完整回归及相关消毒器/并发检查；正式发布另运行 `scripts/verify-release.sh`。历史通过记录不能替代本次结果。
