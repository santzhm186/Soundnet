# Soundnet 项目宪法

当前平台合同为 **3.0.0 / build 100，SDK 2，节点包 ABI 2，磁盘工程格式 v6**。本文规定实现边界和验收要求；不代表本轮集成测试、签名发布或真实宿主验证已经完成。旧讨论稿与本文件冲突的设计不再作为要求，用户当前明确决定优先。

## 1. 平台与节点分层

Soundnet 平台提供画布、图约束、节点发现、通信、执行与生命周期、编辑事务、后台任务、设备适配和工程资源服务。平台版本决定支持哪些接口、信号和保存规则；合成、效果、编排、节奏、模型调用和节点专用 UI 属于节点。

节点在 `nodes/<slug>/` 独立开发、测试、编译和发布。符合当前 SDK 与二进制合同的节点更新不要求更新 Soundnet，不重新编译平台或宿主。平台刷新节点包目录，验证候选包后整体更新可用节点和工程执行图。常规节点不能靠修改中央类型分支、参数名单、编辑器名单或构建文件名单接入。

节点不是任意版本的本机动态库。当前 ABI 使用固定 C 导出入口定位包，再使用 SDK 2 的 C++/Objective-C 接口；加载器检查 ABI、SDK、编译器主版本/libc++ 标记及公共结构尺寸。不兼容时明确拒绝，不把不同布局强行解释为可执行对象。

项目处于早期，不承诺历史旧工程或旧音色逐样本兼容。未知节点及不支持的行为/状态版本保留不可执行占位和原始数据；严格执行/导出拒绝不完整图。已提供的格式转换只覆盖明确实现的输入，不扩张为全量旧版本迁移保证。

## 2. 版本各自负责什么

| 标识 | 所有者与含义 |
| --- | --- |
| Soundnet 平台版本 / build | 平台发布，决定画布、公共服务、通信和工程保存能力 |
| `sdkVersion` / 包 ABI | 节点与平台调用合同；破坏接口布局或语义时由平台升级 |
| 包 `revision` / `sha256` | 单独节点包的构建修订与实际二进制内容；节点重新编译或修正算法可独立更新 |
| `nodeVersion` | 节点行为、端口和配置的解释合同 |
| `stateVersion` | 所存节点状态的解释版本 |
| 工程 `version` | 平台文件格式；磁盘当前 v6，内存和 AU 使用解析后的自包含图 |

包修订不等于节点行为版本。纯文案、保持配置语义的修复无需为了发布新包强行提升 `nodeVersion`。删除参数/端口、改变其含义或状态解释时须调整对应版本，并说明旧实例的处理方式。`nodeVersion` 范围 1–65535，`stateVersion` 范围 1–255；当前按描述符精确匹配，不会自动迁移节点私有配置。

SDK 目前恢复参数、文本和平台支持的素材，不提供通用内核私有运行状态序列化回调。`stateVersion` 不代表播放游标、包络、随机进度或任意 `state` 对象会自动恢复。

## 3. 目录、节点包与刷新

```text
platform/                   公共 SDK、注册目录、加载器、图编译与运行、任务和资源服务
  NodeDescriptor.hpp        描述符、参数、端口、工厂、校验与文案
  NodeKernel.hpp            内核生命周期与块数据
  NodeEditor.h              受归属保护的编辑、任务、试听和设备回调
  NodePackage.hpp           soundnet_node_v2 二进制入口合同
  NodePackageLoader.h/.mm   节点目录扫描、校验、加载与整体发布
  ProjectResources.h        多资源与有序集合公共 API
  resources/、runtime/     不可变素材类型与通用运行服务
nodes/<slug>/               一个节点的源码、专用面板、资源及独立测试
  Node.hpp                  模块描述与工厂
  Kernel.hpp                处理型节点实现；纯后台节点可用 Task.hpp
  Editor.hpp                可选专用 UI
  Tests.cpp                 独立行为测试
  Resources/                可选随包资源
app/、au/、ui/              两种宿主与共享画布
src/                        现有实现与转发入口，不是新节点依赖入口
```

节点只依赖 `platform/`、本目录及明确携带的算法依赖，禁止包含其他节点内部文件、`src/`、`app/`、`au/`、`ui/` 或 `_legacy/`。平台共享算法可以置于公共目录；节点专属算法和配置解析留在节点目录。当前注册的 46 个模块已采用公共描述合同，`legacyAdapter` 不再是接入方式。`comment` 是元数据节点，隐藏 `task-example` 是纯后台样例，不能为它们伪造 DSP。

可分发节点包为 `<nodeKey>.soundnode/`，包含 `manifest.json`、`Node.dylib` 和可选 `Resources/`。清单声明稳定 key、SDK/ABI、构建修订、动态库及内容校验。包内资源同样参与内容校验与刷新身份；平台保存不可变快照，并通过配置/编辑器上下文的 `resourceDirectory` 提供只读资源根，旧实例不因更新而读到新包内容。包资源不能在音频线程读文件。构建器按目录自动收集实现编译单元和资源；`Tests.cpp`、测试目录不进入节点库。自动生成的注册表仅用于静态测试/开发发现，不是发行版必须重新编译的节点名单，不手工编辑。

默认搜索宿主包内 `Resources/Nodes` 和用户 `~/Library/Application Support/Soundnet/Nodes`。用户目录同 key 包覆盖随平台提供的包；同一目录的重复 key 属于错误。`SOUNDNET_NODE_PATH` 可指定冒号分隔的绝对目录，完全替换默认搜索范围，用于开发或测试。

App 与 AU 使用同一加载器。刷新先完成整批候选包校验，再原子替换不可变注册目录；候选包校验失败保留已接受的目录和工程。新目录发布后，宿主暂停播放、失效旧任务并重建工程图；工程准备失败时保留原文档和原执行图，报告具体失败，不发布部分新图。音频线程不能扫描磁盘或加载动态库。当前图与旧面板保有所属目录/代码寿命，旧 Objective-C 类和动态库不在播放过程中热卸载。二进制镜像、包资源快照及注册目录修订各有 512 个的进程预算；加载后发现接口不兼容的镜像同样计数，达到任一预算需重启释放。已接受资源快照保持只读，失败候选的临时快照清理。

平台按二进制内容哈希复用只读代码缓存，跨进程不改写已有文件及其时间戳，避免相同代码每次启动重复接受系统签名校验。首次写入原子发布，复用前校验内容；缓存损坏明确拒绝。磁盘缓存按独立访问标记回收旧版本，并保留当前进程已映射的代码。工程素材和节点包资源不依赖这个代码缓存；包资源仍使用每进程独立的不可变快照。

## 4. 工程环境和保存

完整新工程始终有且只有两个环境节点：`soundnet.timecode` 提供公共帧位置、采样率、运行状态和时间代次；`soundnet.project-settings` 提供处理采样率、精度、导出位深、设备设置及工程位置。普通删除和复制不得破坏其唯一性。局部内核测试可构造无环境图，不代表完整工程可以省略环境。

SDK 2 的生产节点目录必须包含平台指定的 `soundnet.timecode` 和 `soundnet.project-settings`，各一个；两者的 `nodeVersion/stateVersion` 均为 1，`environmentRole` 分别为 `Timecode` 和 `ProjectSettings`。角色不能交给其他 key 冒充。App/AU 的生产刷新调用 `refreshNodePackages(roots, true)`；缺少任一环境模块或版本、角色不兼容时拒绝整批候选，保留旧注册目录和工程执行图。即使包目录内容没有变化也必须检查此合同。默认 `requireEnvironment=false` 仅供独立节点、局部目录测试等用途，不是生产宿主的加载策略。

没有独立节奏节点或全局 BPM。琶音、片段、节拍器等节点拥有自己的速度/拍号，依据公共时间基准计算事件。下游不得用自己的 BPM 重解释上游已确定的帧位置。普通计算无需读取时间码。

工程根由平台实际保存的工程文件所在目录决定。`project.folder` 在未保存时作为默认保存位置，保存/打开后反映实际工程根；它不是节点另行管理产物的授权目录。AU 不把宿主工程位置猜成可写路径。

磁盘 v6 工程文件保存结构、配置和自描述素材引用。素材位于同级同名 `.assets` 目录，例如 `Song.json` 与 `Song.assets/`；移动或备份时携带两者。路径相对工程根，拒绝目录穿越。平台先完整写入素材，再原子提交工程文件；失败不得破坏前一个完整工程。

`assetRef` 保存当前主素材，`textRefs` 保存声明为文件素材的文本，`resourceRefs` 保存多资源表。音频、MIDI、音高映射和 UTF-8 文本均由平台编码、读取和校验。资源引用自描述其类型，不依赖节点必须已安装；缺失模块仍能保存、移动和保留其素材。素材本身缺失或无效时指出具体文件并拒绝打开，不静默丢失。

内存配置包含自包含的 `resources` 表和 `resourceCollections` 有序记录。集合条目通过资源 ID 指向音频、ABC 等内容，不能把历史素材绝对路径藏进文本参数。生成节点全部历史 take 与当前选择一同保存；未保存工程也可在内存中切换历史。任务临时目录由平台管理，完成/取消后清理。v5 及已支持的旧图格式由读入入口转换；旧生成日志只有记录而未保存内容的历史，必须标记不可用，不能伪造素材。已存在的外部历史文件在导入时收集为平台资源，缺失则明确报告。

AU 宿主状态继续保存自包含的解析图和素材；宿主预设不是磁盘 v6 工程文件。不能把 AU 状态保存错误地实现为依赖 Soundnet 外部工程文件夹。

## 5. 描述符、通信与实时边界

节点 key 全局唯一、带命名空间。内部类型用 `nodeTypeID(nodeKey)`，参数用 `parameterID(nodeKey, localKey)`；参数名只在所属节点内唯一，哈希冲突、重复注册和重复端口必须报错。工程保存稳定 key，不保存显示标题作为身份。

数值参数声明单位、范围、默认值、离散性和可选枚举；文本声明默认值、UTF-8 容量、单/多行和读写属性。组合约束由模块 `validateConfig` 实现，加载、图编译与编辑共用。默认数值/文本统一补齐，显式空文本不替换为默认值。未解码文档的验证不能假定素材已载入。

当前图负载仅有音频、MIDI、触发、时间码。`Control`、`Resource`、`TaskEvent` 图端口未实现，须拒绝注册；平台资源集合不等于 `Signal::Resource` 图通信已经可用。

输入只读，输出归当前实例独占；临时视图只在本次调用有效，多输出按稳定端口 ID 访问。`PortMultiSource` 仅支持触发输入，同源重复边不重复投递。`PortOptional` 控制缺线提示，必连输入未连只提示工程未完成，仍允许逐步编辑；所有内核必须安全处理空输入。

SDK 2 的 `PortFeedback` 仅用于允许触发输入参与反馈。编译器通过强连通分量识别实际成环的边，仅对环内声明允许反馈的边增加一个处理块延迟，延迟量为产生事件时当前块的有效帧数，并保留块内帧偏移。普通 Start→Clip 等无环边仍在同块传递。反馈不能伪装成无延迟循环，也不扩展为任意音频/MIDI反馈。变长块下仍须验证事件总帧位置正确。

`prepare/configure` 在非实时线程准备状态。`process/reset` 有界、无阻塞，不分配内存、不访问文件/网络、不调用模型或等待后台任务。处理有效帧数，不能把 128 帧写死为算法前提。资源由 `KernelConfig.audio/clip/model` 提供不可变句柄，配置阶段持有，音频线程只读。

每个实例独占可变状态，实时和离线会话不得共享游标、包络、随机进度或待发事件。 SDK 2 复位时，平台先释放已跟踪的宿主 MIDI/控制器并清空被复位节点已发布的输出，下游通过输入状态比对补相应 Note Off；内核 `reset` 只清内部游标、held/controller 状态，不在下一块重复补发释放事件。MIDI 保留通道与帧位置，Note On/Off 配对；停止、断线、配置变化和溢出不得留下持续音符或踏板状态。拓扑和配置在明确边界整体发布，仍被运行线程使用的对象不得提前回收。

内部音频为 Float32 立体声。项目处理率和设备率分别显示，App 可转换；CoreAudio 设备选择不修改系统默认设备，不绕过输入授权。AU 的设备与实际采样率归宿主。导出位深是文件编码设置，不是处理精度。

## 6. UI 与后台任务

普通控件由描述符生成。专用面板通过 `NodeEditorContext` 编辑配置、创建其他节点、试听 MIDI、控制播放或使用设备服务；不能自行访问中央编辑器或另一实例运行状态。配置提交、资源集合、创建节点均走校验、撤销/重做和保存事务；局部提交省略字段表示保留，显式 `NSNull` 表示删除支持的字段。

节点文案位于 `NodeModule.translations`，以节点类型隔离并回退公共文案，支持中英文。专用面板用 `context.text`，不用导入中央翻译表。稳定 ID、用户文本和自定义名称不翻译。

文件、网络、模型和外部进程在 `TaskService` 执行。任务固定输入快照并绑定工程会话、节点实例、输入版本和任务 ID。删除、输入变化、工程切换或所有者关闭后，旧结果不能提交。节点通过 `submitTask/cancelTask/taskSnapshot` 使用平台任务服务；工作线程不修改工程或控件。

任务有队列/并发预算，取消定期检查并结束外部进程，界面线程不等待耗时取消。成功且仍归属当前输入的结果，才由控制线程经事务发布资源和历史记录。失败、取消或过期结果不覆盖最后完整素材。局部停止只影响目标节点；全图播放停止清理实时状态，后台任务取消是独立操作。

长期开着的面板须通过 `captureTaskContext` 获得最新字段与仍有效的编辑/任务回调；失去归属后不能继续提交。节点只能使用平台授予的回调能力，不能切换任务会话或取消其他节点。

## 7. 演进、协作与完成条件

节点算法、参数、预设、专用 UI 在本目录完成并独立发布。新增公共信号、生命周期、资源类型或保存语义时，先记录输入输出、所有权、线程、停止/失败和保存合同及受影响模块，再同时更新平台与节点。既有用户授权覆盖此工作时直接推进，不另建人为审批流程。

修改前查看工作区与当前文档。并行窗口只修改负责文件，公共接口变化及时协调，不覆盖未提交工作。旧源码/转发入口不能成为新增节点的依赖捷径。

完成需满足：

1. 节点独立构建成包，不修改中央类型分支即可发现、显示、接线、执行。
2. 本目录 `Tests.cpp` 覆盖真实行为、空输入、短块、边界及有状态节点停止/复位；宿主设备边界另有集成验证。
3. 图测试验证实例独立、端口身份、多输出、旁通、溢出和反馈等实际声明的能力。
4. 当前配置、主素材和历史资源保存/重开/移动后恢复；不支持版本占位，非法配置清楚失败。
5. 刷新失败原子保留、更新生效、缺包占位、旧图/面板寿命和代码预算经过验证。
6. 后台任务覆盖取消、删除、输入变化、会话切换和过期结果；中英 UI、单位和默认值正确。

节点修改运行目录测试和相关集成测试。公共接口/运行器修改运行 `scripts/test-all.sh`，按影响运行 ASan/UBSan、TSan。正式发布还需 `scripts/verify-release.sh`、通用二进制、签名、自检及导出验证。只报告本次实际完成的验证，真实设备、Logic/AU 和真实模型推理须分别记录。
