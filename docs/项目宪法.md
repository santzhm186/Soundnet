# Soundnet 项目宪法

适用基础为 **2.9.1 / build 91**，制定日期为 2026-11-09。本文是各开发窗口与人员共同遵守的工程边界。旧《节点与连接标准》讨论稿只保留为历史资料；与本文不一致的设计不再作为实施要求。

## 1. 平台与节点

平台提供节点注册、通信、执行与生命周期、资源和工程服务。声音合成、调制、编排、节奏、模型调用等具体功能由节点实现。

项目处于早期，当前不承担旧工程及旧声音行为的兼容承诺。已有历史解析入口可以保留，但不作为新增节点的设计约束。不支持的行为或状态版本保留不可执行占位或清楚拒绝，不能静默按另一种含义执行。

## 2. 工程环境与节奏

完整工程创建时自动建立且保持各一个环境节点。

| 节点 | 职责 |
| --- | --- |
| `soundnet.timecode` | 公共帧位置、采样率、运行状态与时间代次；需要时间的节点按需使用 |
| `soundnet.project-settings` | 项目处理采样率、处理精度、导出位深、音频输入输出设备配置 |

环境节点不能被普通删除或复制操作破坏其唯一性。底层内核测试可以构造不含环境节点的局部图；这不等于完整工程可以缺少环境。

**不设置独立节奏节点，不设置全局 BPM。** 琶音、片段、节拍器等相关节点自行声明速度、拍号或节奏型，并根据公共时间位置计算事件。节点内部可以使用拍，节点间定时事件必须保留共同时间基准和块内帧位置。下游不能再用自己的 BPM 重解释上游已确定的事件时间。

普通计算无需读取时间码。音频处理仍须遵守实际处理采样率和本次有效帧数。

内部音频接口目前为 Float32 立体声。项目处理采样率与音频设备采样率分别显示，独立 App 可由混音器完成转换。设备配置使用 CoreAudio UID 或 `system`，不改系统默认设备；输入选择在开启输入后生效，不自动绕过麦克风授权。AU 的设备与实际采样率由宿主控制。导出位深属于文件编码设置，不能冒充处理精度。

## 3. 目录和依赖

```text
platform/                   公共接口、任务和工程环境服务
  NodeDescriptor.hpp        描述符与参数/端口约定
  NodeKernel.hpp            内核生命周期和通信数据
  NodeEditor.h              专用面板、编辑事务与后台任务回调
  resources/                公开的只读音频、MIDI 与模型资源类型
  runtime/                  通用运行辅助
nodes/
  <slug>/
    Node.hpp                节点描述、参数、工厂与校验
    Kernel.hpp              处理型节点的运行实现；纯后台节点可用 Task.hpp
    Tests.cpp               独立行为测试
    ...                     可选 UI、资源、预设和说明
  _legacy/                  旧引擎、处理器注册与适配清单，禁止新模块依赖
  GeneratedRegistry.hpp     自动发现结果，禁止手工编辑
  GeneratedEditors.hpp      可选专用面板发现结果，禁止手工编辑
src/                        图编译、工程格式及仍待迁出的既有实现
app/、au/                   独立应用与 Audio Unit 宿主适配
ui/                         共享画布、检查器与编辑事务
```

同一节点可有多个文件。普通修改应局限于自身目录。节点不能包含其他节点的内部头文件，不能直接操作画布、宿主设备或另一节点的运行状态。

当前自动构建入口包含 `Node.hpp` 与可选 `Editor.hpp`，实现可拆成它们包含的多个头文件。新增任意 `.cpp` 或资源文件不会自动变成构建/打包输入；确需独立编译单元或随包资源时，先完善公共发现规则，不能为单个节点新增中央文件名单。

2.9.1 已将描述符拆到各节点目录，并建立通用内核入口。既有音频处理器放在所属目录的 `Processor.hpp`，部分 MIDI/合成算法放在所属目录的 `LegacyRuntime.inc`，仍由过渡运行器调用；`nodes/_legacy/` 保留旧引擎和处理器注册。旧 `src/` 头文件保留为转发入口。**代码已分目录不代表内核全部迁移完毕。** 后续按节点逐个迁入自身 `Kernel.hpp`，新节点不得复制中央类型分支模式。

过渡节点须同时声明 `legacyAdapter` 并列入 `nodes/_legacy/adapter-keys.txt`，生成器据此阻止新增模块绕过公共内核接口。普通新节点不得扩充此清单。已有节点完成通用内核和集成验证后，移除其 `legacyAdapter`、清单条目与无用旧分支，再重新生成注册表。纯后台任务节点可声明 `CapTask`，通过公共任务服务执行，无须伪造音频内核。

## 4. 注册、参数与 UI

- 节点名称全局唯一且带命名空间，例如 `soundnet.gain`。目录名使用小写字母、数字和连字符。
- 类型使用 `nodeTypeID(nodeKey)`，参数使用 `parameterID(nodeKey, localKey)`。无需领取全局数字区间，哈希冲突与重复注册必须报错。
- 输入端口 ID、输出端口 ID 各自在节点内唯一，数值参数名在节点内唯一。输入和输出可使用相同 ID，例如 `audio`。工程按稳定名称保存，显示标题、语言和分组可以独立调整。
- 数值参数声明单位、范围、默认值、离散性和可选枚举；文本参数声明默认值、UTF-8 长度预算、单/多行及只读属性。
- 起止范围、参数组合等约束放入模块的 `validateConfig`。图编译、加载和编辑统一调用，不在平台里补节点例外。
- 普通控件由描述符生成。专用 UI 通过工程编辑事务修改配置，支持撤销、重做与保存，不直接改运行状态。
- 展示提供中英文，节点自有文案放入本模块的 `NodeModule.translations`，按节点类型查找并回退公共文案；同名文案在不同节点间互不覆盖。稳定 ID、用户自定义名称和用户文本不进入翻译表。

构建扫描 `nodes/*/Node.hpp` 并生成注册表。常规新增节点不修改中央目录、参数白名单、渲染类型白名单或构建源码名单。

## 5. 通信与生命周期

输入只读，输出由当前节点独占。数据在本次调用内有效，内核不能缓存上游临时缓冲的裸指针。多输出按各端口 ID 处理，不能统一回落到出口 0。

当前公共内核路径提供音频、MIDI、触发和时间码。`Control`、`Resource`、`TaskEvent` 的图内负载尚未实现，当前 SDK 拒绝这些端口；使用前须补齐公共数据结构、路由和测试。

端口负载由 `Signal` 决定，不能用 `RoleTrigger` 将其他信号伪装成触发。`PortMultiSource` 仅用于触发输入，编译器按标志限制不同来源；重复的同一来源端口不重复投递。`PortOptional` 是接线完整性约定，必连输入缺失仅提示工程未完成，以允许逐步编辑；所有内核仍须安全处理空输入。SDK 1 拒绝 `PortFeedback`，未来启用前须定义并验证确定的延迟和跨块帧偏移；旧适配反馈暂保留，不承诺固定一块延迟。时间码端口承载公共帧位置和运行状态。

`prepare/configure` 在非实时线程准备状态。`process` 与运行期 `reset` 在所属执行线程调用，要求有界、无阻塞、无文件/网络访问、不分配内存。支持短块与变长有效帧数，不把当前 128 帧实现选择写死在算法中。

每个实例独占可变状态。不同实例、实时会话与离线会话不能共享播放游标、包络、随机进度或待发事件。MIDI 必须配对 Note On/Off，参数改变、断线、停止和溢出后仍须收音。

配置和拓扑在明确边界整体发布。资源先完整准备，再发布只读结果。音频线程不能遍历控制线程正在替换的容器，也不能回收仍被音频线程使用的资源。

`KernelConfig.audio/clip/model` 是已解码的不可变资源句柄，类型来自 `platform/resources/`。内核在 `configure` 持有需要的句柄；`process` 只读其内容，不解码、不替换所有权。`src/AudioSample.hpp` 等仅保留转发兼容入口，新节点使用公共资源类型。

配置校验与执行通过同一解析规则补齐描述符的数值、文本默认值，仅向声明相应 `CapAsset*` 的节点传入资源。显式空文本不替换为默认值。未解码文档的验证不能假定资源已载入；所需素材的加载失败由资源加载流程报告。

## 6. 后台任务与停止

长计算、文件、模型和外部进程使用 `TaskService`，不得放进实时 `process`。任务固定输入快照，绑定工程会话、节点实例、输入版本和任务 ID。只允许仍匹配当前归属的结果提交。

局部停止只作用于目标节点；全图停止暂停执行并清理实时状态。后台取消独立于播放停止，由服务明确处理。删除节点、改变任务输入、切换工程和关闭任务所有者应阻止过期结果提交。任务定期检查取消，并结束外部子进程。

任务并发与队列有明确预算。取消不在界面线程等待耗时进程退出。失败、取消或过期结果不覆盖上次完整素材。通过任务状态或工程诊断说明原因，不静默显示成功。

声明 `CapTask` 的专用面板通过 `NodeEditorContext.submitTask/cancelTask/taskSnapshot` 使用任务服务。平台绑定工程和实例身份，在控制线程接收结果并通过正常编辑事务提交；节点不能另行切换服务会话或取消其他节点。隐藏的 `nodes/task-example/` 是独立异步模块样例，不要求修改中央编辑器类型分支。

## 7. 标准演进与并行协作

标准允许随节点制作增减。

| 变化 | 处理方式 |
| --- | --- |
| 节点算法、参数、预设、专用 UI | 在节点目录实现，更新该节点声明、版本与测试 |
| 公共信号、内核接口、生命周期、资源规则 | 先记录接口提案、影响节点与适配方式，再更新平台与受影响模块 |

接口提案应回答输入输出、所有权、线程、停止/失败和保存语义。已有任务授权覆盖变更时直接实施，不额外建立人工批准流程。涉及其他窗口正在修改的文件时，先协调文件归属，不覆盖其工作。

新增可选字段应有明确默认行为。破坏接口的变化提升 SDK 或节点版本并适配受影响代码。当前不要求为早期旧工程另写迁移体系，但必须识别不支持的版本。

三个版本用途不同：`sdkVersion` 标识公共执行接口，`nodeVersion` 标识节点行为/配置合同，`stateVersion` 标识所存节点状态的解释版本。当前按描述符精确匹配，不会自动迁移旧版本；提升后既有实例可能成为占位，需要明确告知受影响开发窗口。纯文案调整不必升行为版本。删除参数/端口、改动其含义或状态布局时记录新旧解释与处理方式。

当前 SDK 保存参数、文本和已支持素材，不提供通用内核私有状态序列化/恢复回调。`stateVersion` 校验不代表游标、包络、随机进度或自定义 `state` 对象会自动恢复。新节点如需持久化这些内容，须先扩展公共状态接口并验证加载、停止与实例隔离。

每个窗口开始前查看当前代码、宪法和工作区改动，结束时说明节点的输入输出、状态、取消方式、实际验证及限制。

## 8. 完成条件

1. 不修改中央类型分支即可注册、显示、接线和执行。
2. 本目录 `Tests.cpp` 可独立编译，覆盖真实行为、边界和有状态节点的停止/复位。
3. 图集成验证覆盖实例独立、端口身份、多输出或旁通等实际使用能力。
4. 保存后恢复当前版本配置，非法配置清楚失败，未知/不支持版本不误执行。
5. 实时状态与发布变化通过有关并发检查；任务覆盖取消、删除、会话切换与过期结果。
6. 中英界面、单位与默认值符合描述符，未实现能力明确列为待办。

平台修改运行全套回归，并按影响运行 ASan/UBSan 与 TSan。正式发布还需通用二进制、签名、自检与导出验证。只报告实际完成的验证，不把历史验证当成本次结果。
