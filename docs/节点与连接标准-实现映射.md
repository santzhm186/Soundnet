## 2.81 补充：展示与停止控制

- `ParamSpec::group` 是只用于展示的参数分组元数据；检查器从描述符派生，节点、参数与端口稳定标识保持原样。
- 中英翻译只作用于显示文本。工程保存仍使用原稳定 ID，自定义名称不翻译。
- `Engine::setProcessingEnabled(false)` 在音频块边界清理状态并持续静音；显式恢复才重新执行。App / AU 的 MIDI 队列按停止代次丢弃旧事件，保留恢复后的新输入。
- `Trigger.Stop` 仍是发往指定节点的图内事件；工具条「停止」是全图运行控制，两者语义分开。停止不修改工程参数。
- 离线导出新增原子取消标记，并在写入最终目标前检查；素材载入可取消应用结果。这些是具体入口的取消机制，通用异步 `Cancel Run` / 时间域服务仍属待办。

## 1 本轮重构解决的问题

标准附录 A 列出 7 条基线冲突。本轮以“单一事实来源”为主线重写契约层，逐条对应如下。

| 编号 | 基线问题 | 本轮的处置 | 位置 |
| --- | --- | --- | --- |
| C1 | 一个节点散落在 6 个文件、约 20 处 | 新增 `NodeSpec` 描述符；`NodeRegistry` 退化为只读视图；引擎、编辑器、校验、离线导出全部从描述符取值 | `src/NodeSpec.hpp`、`src/NodeRegistry.hpp` |
| C2 | `CommentNode`(46) 被当作类型合法上界 | 删除数值上界：合法性 = 注册表命中 + 可实例化；新增类型只需追加条目 | `validNodeType`、`compileGraph` |
| C3 | 端口语义靠 `inputs[0]`、`clockSlot` 等位置硬编码 | 端口有稳定 ID 与角色；引擎按角色取主输入、时钟、侧链，输出汇聚按能力标志；多输出节点的出口号随连线保存 | `PortSpec`、`PlanNode`、`InstanceGraph::publish/render` |
| C4 | 触发反馈白名单与真实端口错位；重复连线使事件翻倍 | 反馈豁免改为端口上的 `PortFeedback` 声明；完全重复的触发连线被丢弃并给出诊断；调度栈做深度保护，超深链路延后一块而不是丢弃 | `PortFlags::PortFeedback`、`compileGraph`、`InstanceGraph::dispatch` |
| C5 | 参数作用域形同虚设；整数量未标离散 | 参数只接受描述符声明的集合；离散标记与内核实际取整行为对齐；v3 文档中越界参数在迁移时丢弃，v4 直接报错 | `nodeParamSpec`、`ParamSpec::discrete`、`decodeGraph` |
| C6 | 能力标志与实现不一致（旁通） | 旁通成为描述符能力：检查器只在可旁通时显示、JSON 对不可旁通节点写 `bypass` 直接拒绝、运行计划忽略未声明能力 | `CapBypassable`、`decodeGraph`、`compileGraph` |
| C7 | 隐式约束没有运行期保护 | 端口访问全部有界；`notePort()` 对越界索引回落到主端口；端口数量、信号、重复源在编译期检查；类型 0 不再解析为占位节点 | `nodePort`、`Runtime::notePort`、`compileGraph` |

## 4 关键设计决策

### D1 实例 ID 保持数值

标准示例用字符串 `instanceId`，本实现继续用工程内唯一的 `uint64`（保存为 `id`），并新增每节点可选 `name` 作为显示名。理由是引擎、运行时容器、撤销栈与宿主同步都以数值 ID 索引；改成字符串需要重写运行期映射而没有行为收益。类型身份（`nodeKey`）与端口身份（字符串）已按标准落地，只有实例身份仍是数值。

### D2 参数的“双身份”

参数同时拥有永久数值 ID（与 AU 参数表、旧工程兼容）与稳定字符串键（v4 可读、可人工编辑）。`ParamSpec` 把两者绑定，`paramKey`/`paramIdForKey` 是唯一转换点。v3 文档接受数值键，v4 文档只接受稳定键；两者在迁移后指向同一 ID。

### D3 文档双表示，边界规范化

- 编辑器内存中的文档就是 v4：`nodeKey`、参数键、端口名。
- 引擎使用索引：`GraphNode::type`、`GraphEdge::port`、`PlanNode::inputs`。
- `normalizeGraph` 是唯一转换点：有端口名以名字为准，没有则按序号补名字；名字无法解析时直接报错，绝不静默落到端口 0。

### D4 端口角色取代位置约定

| 角色 | 用途 | 使用方 |
| --- | --- | --- |
| `RoleMain` | 节点的主数据输入/输出 | 振荡器、采样器、编排器出口 |
| `RoleClock` | 时间来源 | Clip、ARP、力度、走向 |
| `RoleSidechain` | 检测输入 | 压缩器 |
| `RoleTrigger` | 因果事件 | 全部逻辑节点与播放器 |
| `RoleOutput` | 终端汇聚 | 硬件/DAW/主输出 |

引擎不再按 `inputs[0]`、`clockSlot=1` 取数据，而是按“信号 + 角色”查找；多输出节点的出口号随连线保存（`PortLink::port`），因此编排器的 `middle` 出口接到任何下游都能正确取到对应音符端口。

### D5 触发投递与反馈

- 投递立即发生，保证 Clip 在自己的循环边界收到停止事件（延迟一块会让循环多跑一轮）。
- 递归只由 `Start/Stop/Count/Wait/Random` 的 `trigger()` 回调产生，深度超过 64 即停止，避免音频线程栈溢出。
- 完全重复的触发连线在编译期丢弃，修复了基线“同一事件翻倍”的问题。
- 反馈端口（Clip/ARP/Progress/Wait 的触发输入）不参与拓扑排序，允许“循环完成 → 计数 → 停止 → 回到同一 Clip”这类结构。

### D6 未知节点

| 场景 | 行为 |
| --- | --- |
| 编辑器打开、自动保存恢复 | `allowUnknownNodes=true`：节点标记 `unavailable`，连线原样保留，画布红框提示，其余子图正常 |
| 导出、宿主发布、严格校验 | 默认拒绝，并说明缺失的 `nodeKey` |
| 再次保存 | 未知节点的 `nodeKey`、坐标、参数、素材与连线原样写回 |
| 下游收音 | 主音符输入断开（上游被删或变成缺失节点）时，MIDI 输出在下一块释放已发音符 |

### D7 类型编号仍是内核选择器

`type` 不再参与“是否合法”的判断，只用于选择运行内核与 DSP 工厂。新增节点只需：注册描述符 → 在 `Runtime` 构造与渲染分派中加入内核分支（或用 `makeAudioProcessor` 注册处理器）。数值编号只增不改，`FirstAppendedNode=47` 之后可以继续追加。

4. **执行状态接口**：`runId`、输入版本、`Cancel Run`、快照与缓存键（标准 6.1、9.7）。
5. **保留表与正式契约 1.0**：把“不得复用”的约定固化为可执行清单，并发布带版本的正式契约。

这些条目的描述符字段已经存在（`CapTask`、`CapSnapshot`、`TimeMode`、`Signal::Control/Resource/TaskEvent`），落地时不需要再改契约层。

### D8 文本参数用 `NodeSpec::texts` 而非 `ParamSpec` 扩展

参数表的身份是"永久数值 ID + 稳定键 + 数值区间"，而 prompt/歌词是任意长度文本，没有区间也不该占用 ID 段。因此文本参数在描述符中以 `TextSpec{id,label}` 列表声明，工程格式中以节点级 `texts` 字典保存；检查器从描述符生成多行文本框，撤销与复制沿用节点级编辑。`paramSpec()` 只回答数值参数问题，两者互不冒充。

### D9 生成由显式按钮提交，触发端口只控制播放

原策划把"触发到达"作为提交入口。实施时改为检查器按钮显式提交，理由是：走带开始、循环边界或误接线都会触发分钟级外部任务，代价太大且不可预期；播放本身仍由触发端口控制，与音频片段一致。若后续需要"一次播放触发一次生成"，应在图中加显式确认节点，而不是让触发隐式承担提交语义。

### D10 ABC→MIDI 在引擎内做，不建"乐谱"素材类型

乐谱的价值在于它可以被编辑，而 Soundnet 已有的编辑入口只有钢琴卷帘，因此乐谱必须在进入工程时就变成普通 MIDI 剪辑，而不是一种新素材。转换器是纯文本解析（`src/AbcScore.hpp`，无模型、无第三方库）：头部 `X/T/M/L/Q/K/V` 决定单位时值、调号与速度，正文支持附点/连线/和弦/连音/破节奏/变音记号与多声部。已知不展开反复记号（`|:` `:|` 按小节线处理），因为生成模型的产出基本不含反复；这一限制记在 `Score::warnings` 之外的文档里，将来若需要应在转换器内做展开而不是改素材格式。

ABC 文本在 AI 节点与剪辑节点各存一份：前者是回喂源（用户改这里再按「按乐谱重新生成」），后者是导入时刻的快照，用于工程自描述与追溯。两份互不同步是刻意的——钢琴卷帘的改动属于 MIDI 域，回喂属于 ABC 域，跨域自动回写会产生无法预测的语义。
