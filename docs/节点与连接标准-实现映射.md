# 节点与平台实现映射（3.0.0 / SDK 2）

本文件与 [项目宪法](项目宪法.md) 配套。平台为 **3.0.0 / build 100**，公共执行接口 SDK 2，节点包 ABI 2，磁盘工程格式 v6。此处记录代码职责、设计边界和验证入口，不将正在进行的集成或发布写成已验收。

## 公共入口

| 职责 | 代码入口 | 合同 |
| --- | --- | --- |

旧 AU 参数存储与历史引擎测试仍有保留代码，但生产宿主只执行实例图：没有图时输出静音，不能回退到内嵌旧乐器绕过节点包目录。当前节点不依赖这些旧入口。

## 节点适配范围

当前共有 **46 个模块描述符**，包含隐藏开发样例，数量不等于节点库可见条目数。处理型节点通过本目录 `Kernel.hpp` 和公共 `kernelFactory` 执行，不再注册 `legacyAdapter`。

| 分组 | 节点目录 | 运行合同 |
| --- | --- | --- |
| 音频/合成/效果 | `oscillator`、`noise`、`sampler`、`audio-clip`、`mixer`、`gain`、`filter`、`eq`、`reverb`、`delay`、`compressor`、`limiter`、`noise-gate`、`chorus`、`tremolo`、`bitcrusher`、`phaser` | 各节点独立内核与状态，处理器算法保留在本目录 |
| MIDI/音乐 | `midi-clip`、`voice-arranger`、`chord`、`progression`、`arp`、`transpose`、`scale-quantize`、`channel-filter`、`velocity`、`note-echo`、`note-model`、`midi-split`、`metronome` | 节点自己的配置/节奏，公共 MIDI/时间/触发合同 |
| 触发流程 | `start`、`stop`、`wait`、`count`、`random` | 公共触发事件，SDK 2 仅实际环内反馈边增加块延迟，无环边同块传递 |
| 宿主 I/O | `audio-input`、`audio-output`、`midi-input`、`daw-midi-input`、`midi-output` | 公共宿主缓冲/回调；硬件与 AU 环境留在宿主适配层 |
| 生成 | `ace-step`、`yue2` | 独立描述符/播放内核/任务/面板；共享协议和平台历史资源服务 |
| 环境 | `timecode`、`project-settings` | 完整工程各一个；设备/工程根由平台应用 |
| 非 DSP | `comment`、`task-example` | 纯元数据注释、隐藏纯后台样例，不伪造处理内核 |

源码采用公共接口不自动等于全部行为验收完成；每个节点仍需目录测试、相关图/宿主测试和保存验证。第三方节点同样受合同约束。

## 刷新、版本和资源语义

平台刷新的是 `.soundnode` 包目录。单个节点由自己的源码和 SDK 独立编译；普通修订不提高平台版本。包 revision/hash 与节点行为/状态版本分别管理。默认先读取包内 `Resources/Nodes`，再读取用户 `~/Library/Application Support/Soundnet/Nodes`，用户同 key 包覆盖内置包，同目录重复拒绝。

候选注册目录校验完后整体发布，运行图保有其代码世代。旧 Objective-C 类/动态库不热卸载，二进制镜像、资源快照及注册目录修订各有 512 个的进程预算，重启释放。SDK 不兼容、哈希错误和冲突必须明确失败；失败不应发布半个目录。已加载但接口无效的镜像同样计数，失败资源快照清理，已接受快照不改写。

工程按 nodeKey、稳定参数/端口名、nodeVersion/stateVersion 保存。行为/状态版本精确匹配，不支持的模块占位保留；导出拒绝错误解释。没有通用内核私有运行状态恢复回调，不将 `stateVersion` 说成恢复播放游标的实现。

v6 统一保存当前素材与全部历史资源。`resources` 是内存/AU资源表，`resourceCollections` 是角色到资源ID的有序记录；磁盘改为 `assetRef/textRefs/resourceRefs`，引用自描述类型和相对路径，缺失模块不妨碍保留资源。v5 文本字符串引用可读取；旧文本 take 日志导入时收集仍存在的文件，缺文件报错，原本没有内容的历史记录明确不可用。节点不再生成隐藏绝对素材路径。

工程根等于实际工程文件目录。`project.folder` 是未保存默认位置/保存后的根显示，不另指向独立归档树。AU 状态保持自包含；未保存工程可在内存中保存并切换历史。

MIDI Clip 保存标准 MIDI 通道事件，包括 CC、弯音、通道/复音触后、音色切换；节点按自身 BPM 运行。MIDI 接收端决定控制器的音色/音量语义。停止、循环、定位和断开须释放音符与控制器状态。

## 明确未承诺的公共能力

- `Control`、`Resource`、`TaskEvent` 图内负载和路由；平台素材集合不代表这些端口已实现。
- 完全独立于音频回调的数据图求值调度。
- 音频分块存储、流缓冲、计算缓存和跨会话时间域转换。
- 内核私有状态通用序列化/迁移，以及跨任意 clang/libc++ 的稳定二进制兼容。
- 任意音频/MIDI 无延迟反馈、可变延迟补偿与完整的逐节点尾音策略。
- 播放中热卸载 Objective-C 类、无限累计已加载代码版本。

这些能力需要先扩展平台合同及测试，再由节点采用。
